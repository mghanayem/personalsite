TASK: The "Link" fields on Cards Grid cards (link_type, link_value, 
link_new_tab) are not being saved. Clicking "Save Section Changes" 
resets them back to "None" instead of persisting the selected value. 
Debug this end-to-end and report which step was broken before fixing 
it — don't just patch the symptom.

CHECK EACH STEP IN ORDER:

1. DATABASE
   - Confirm the link_type, link_value, and link_new_tab columns 
     actually exist on the cards table (or wherever card data is 
     stored) — check if the migration that was supposed to add them 
     actually ran
   - If the columns don't exist, the save is silently failing on 
     those fields even if everything else looks correct

2. FRONTEND FORM STATE
   - Confirm the Link dropdown, page picker, and URL field are 
     properly bound to the section's editable state (controlled 
     inputs), not just visually showing a value without updating the 
     underlying data the Save button will submit
   - Log or inspect the actual payload being sent when "Save Section 
     Changes" is clicked — confirm link_type, link_value, and 
     link_new_tab are present in that payload with the values I 
     selected, not "none"/empty

   - Confirm the API route handling the save actually reads

     original card fields (title, icon, description) but never

     update statement
   - Confirm there's no schema validation step (e.g. a Zod/Joi schema)

4. POST-SAVE REFRESH

     itself worked

REPORT BACK: which of these four steps was the actual point of 
failure, and confirm with a test — set a card's link to an internal
