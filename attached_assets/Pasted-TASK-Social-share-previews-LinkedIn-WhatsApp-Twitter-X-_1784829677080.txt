TASK: Social share previews (LinkedIn, WhatsApp, Twitter/X, Facebook) are showing generic, wrong titles/descriptions and no image for every page, instead of the per-page values already saved in the SEO Settings panel. Fix the actual <head> tags each page outputs.

DIAGNOSIS TO CONFIRM FIRST

View source (not DevTools — actual "View Page Source") on a real page, e.g. /en/p/cash-flow-forecast-calculator, and check the <meta property="og:..."> and <meta name="twitter:..."> tags. If they show a generic site-wide value (e.g. "Mohammad Ghanayem Portfolio") instead of that page's actual SEO Title/Description, that confirms the bug: these tags are hardcoded/static instead of being generated per-page from the SEO Settings data already stored in the database.

FIX
PER-PAGE OG AND TWITTER TAGS In the template/layout that renders <head> for every page (home, blog posts, custom pages, both languages), replace any static or hardcoded values with the actual per-page SEO fields: <title>{{seo_title || page_title}}</title> <meta name="description" content="{{seo_description}}"> <meta property="og:title" content="{{seo_title || page_title}}"> <meta property="og:description" content="{{seo_description}}"> <meta property="og:image" content="{{seo_og_image || site_default_og_image}}"> <meta property="og:url" content="{{canonical_url}}"> <meta property="og:type" content="website"> <meta name="twitter:card" content="summary_large_image"> <meta name="twitter:title" content="{{seo_title || page_title}}"> <meta name="twitter:description" content="{{seo_description}}"> <meta name="twitter:image" content="{{seo_og_image || site_default_og_image}}"> This must pull from that SPECIFIC page's saved SEO Title, Meta Description, and Open Graph Image — not a global/site-wide constant. Confirm this is happening in the actual server-rendered HTML (view source), not just in client-side JavaScript that runs after the page loads — most social platforms and messaging apps only read the initial server-rendered HTML and do not execute JavaScript when generating a preview.
SITE-WIDE DEFAULT OG IMAGE (fallback) Add one site_default_og_image setting in /admin/settings (a single 1200x630 image, e.g. a professional headshot or branded card). Any page that has NOT set its own Open Graph Image in the SEO panel should fall back to this default — so no page ever shares with a blank image, even before every page has been individually configured.
ARABIC PAGES Confirm the same fix applies to the Arabic (default route) version of every page, using the Arabic SEO Title/Description/Image fields — this needs to work identically on both language versions, not just /en routes.
CANONICAL URL PER LANGUAGE Confirm og:url reflects the actual URL of the specific page being shared (including /en/ prefix where relevant) — not a hardcoded homepage URL.
